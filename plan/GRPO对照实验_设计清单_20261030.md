  k 直方图与训练池规模，决定 G1 用不用难例富集。
- **命令**（AutoDL，MVP/tests 下）：

```bash

# 2. k 分布 rollout ×2 份数据（探针 50 条 + 新题抽样 100 条）
```

- **判读**（读 k 直方图 + `.rows.jsonl`）：
  - 健康：k=1~3 显著非零（有梯度），k=0/k=4 两头都有（筛选有意义）；
  - 全 k=4 → 换难例富集池重测，仍全 4 则 GRPO 无题可训，转「数据再加难」；
  - 全 k=0 → reward 打分或数据坏了，先跑单测 `python3 -m unittest discover -s unit`；
  - 顺手看 R_length 是否仍大面积归零：若 CoT 分位漂移，按打屏建议上调
    `lib/reward_fns.py` 的 120/200/320 三档并同步单测。

### G2 · KL 系数对照（β_KL 0.04 → 0.0）

- **目的**：量化 KL 正则的「防遗忘税」——reward 涨幅 vs eval 泛化/格式稳定性的权衡。
  β=0 是 reward hacking 最容易现形的配置，也是面试「KL 在 GRPO 里干嘛的」的实测素材。
- **触发/判据**：G1 若 reward 涨但 gold500 格式或 F1 掉 → β 是第一嫌疑人，本枪必跑；
  G1 平稳则作为消融补枪。

```bash
DATA=/root/autodl-tmp/datasets/rl_round1/grpo_train.jsonl MODEL=/root/autodl-tmp/models/Qwen3-4B-Instruct-SFT-R2 \
EVAL_FILE=/root/autodl-tmp/datasets/rl_round1/grpo_eval.jsonl \
GRPO_ARGS="--num_train_epochs 2 --beta_kl 0.0" \
./scripts/run_grpo_train.sh --tag=G2_kl0
```

- **判读**：β=0 vs 0.04 对比 eval reward 曲线与 gold500 gate4。β=0 后期塌 → 0.04 保留
  且拿到「KL 必要性」实证；两者无差 → 面试口径改为「小数据短训下 KL 影响有限」。

### G3 · 学习率对照（2e-5 → 1e-5 / 5e-5）

- **目的**：框定 GRPO 的 lr 安全区。RL 的 lr 比 SFT 敏感一档，5e-5 可能直接把阶梯奖励
  打穿（门禁短路飙升）。
- **命令**：同 G1，`GRPO_ARGS="--num_train_epochs 2 --learning_rate 5e-5"`，
  tag `G3_lr5e5`；若崩再补 `G3b_lr1e5`。
- **判读**：门禁短路占比与 reward 方差为主要信号；取「reward 稳涨 + 短路占比下降最快」者。

### G4 · 组规模对照（G=4 → G=8）

- **目的**：G=8 组内阶梯档覆盖更全（0.5/0.7/1.0 三档更容易同时出现），优势差更可信；
  代价是同题数下 rollout 翻倍。
- **触发条件**：G0/G1 显示 k=1~3 组占比 <30%（组内太齐，G=4 拉不开差距）。

```bash
DATA=/root/autodl-tmp/datasets/rl_round1/grpo_train.jsonl MODEL=/root/autodl-tmp/models/Qwen3-4B-Instruct-SFT-R2 \
EVAL_FILE=/root/autodl-tmp/datasets/rl_round1/grpo_eval.jsonl \
GRPO_ARGS="--num_train_epochs 2 --num_generations 8 --per_device_train_batch_size 4" \
./scripts/run_grpo_train.sh --tag=G4_gen8
```

### G5 · Reward 消融双枪（面试防御素材，G1 胜者配置上各只动一轴）

- **G5a · 关 R_length**：`r_length` 硬置 0（代码临时开关或加 `--disable_r_length`）。
  目的：证明 CoT 压缩（p50 → 120~200 理想区）是 R_length 的功劳而非 SFT 遗产。
  读数：CoT token p50/p95 + sentiment/hard_case F1 是否同步掉。
- **G5b · scale_rewards 除 std 对照**：临时撤 `_patch_scale_rewards_none` 补丁
  （`scale_rewards` 回 trl 默认）。目的：实测「阶梯分离散分除 std 会放大组内噪声、
  诱导学错排序」这条已在 `lib/reward_fns.py` 写死的口径，拿到正反两面证据。
- **判读**：两枪都只看「与 G1 的差值」，差值即消融归因，直接进面试叙事。

## 2. 判据（gold500_test.jsonl 上 evaluate_sft 模式 B；过程指标看训练日志）

- **主指标**：sentiment Macro-F1、hard_case Macro-F1（不得低于 SFT 胜者 R2 的
  92.04 / 58.96 减 1pp 容差——GRPO 的本职是压 CoT 与提格式/溯源，不是拿判别 F1 换的）
- **副指标**：gate4 格式三项（目标：R2 的 JSON 99.6% → 100%）、evidence 严格子串率
  （目标 ≥99%，门禁② 短路率下降）、CoT token p50（目标落 120~200 理想区）
- **选定规则**：
  - G1~G4 取「主指标不降 + 副指标改善最大」者，平手取配置简单者（β=0.04、lr=2e-5、G=4）；
  - 任一枪出现 reward 涨 + eval F1 跌 → 记 reward hacking 实锤，该配置淘汰并进面试反面素材；
  - 门禁短路占比不随训练下降 → 查数据池格式污染，先修数据再谈训练。

## 3. 待调超参脑暴（非排期，逐项带触发条件）

- **P0 · temperature（0.7 → 1.0）**
  探索多样性：组内轨迹太同质时 k 直方图会挤在两头。触发条件：k=0+k=4 合计 >80%。
- **P1 · num_iterations / mini-batch 内更新次数**：trl 0.14 的 μ（每批重复利用次数）。
  触发条件：样本效率不足（reward 平台太早）且 24GB 显存有余量。
- **P1 · 数据配比（难例富集比例）**：G0 判读后按 7 类 hard_case 桶定配额，
  对齐数据工程六桶口径；严禁把 SFT 见过的题混进来刷 k=4。
- **P2 · β_KL 0.1**：G2 若 β=0 崩得快、0.04 也抖，加一档强正则。
- **P2 · eval 基线集扩容（32 → 64）**：greedy 后仍见 reward 均值抖动 >0.05 时加。
- **P3 · LoRA r16 → r8（RL 头）**：RL LoRA 更小容量 = 天然正则。触发条件：G2~G3 全崩、
  怀疑 RL 头过拟合阶梯奖励。
