# 实验报告：Loss 结构消融（POC1 vs POC2 vs POC3）

**日期**：2026-10-29（R1_Anchor 旁证组同日）
**基座**：Qwen3-4B-Instruct-2507（Non-thinking，`tie_word_embeddings=True`）
**数据**：750 条纯领域（train 673 / val 75）
**训练**：LoRA r=16 / α=32（7 个线性层），lr 1e-4，cosine，有效 batch 8，3 epoch = 255 步
**评测**：`gold500_test.jsonl`（500 条），`evaluate_sft.py` 模式 B，统一 strict 分母口径（解析失败即丢弃）

> 本报告回答一个问题：**监督信号应该怎么给？** 全部 token 等权学（POC1）、把 JSON 死模板屏蔽掉（POC2）、
> 还是在此基础上对字段分权重（POC3）。轮数与学习率变量见另两份报告。

---

## 1. 实验目的

73 条探针阶段已解决「格式学不会」的问题（协议 token 解冻，见 2026-10-24 报告）。数据扩到 750 条后，
剩余问题是**判别力**：sentiment 与 hard_case 的 F1 还有多少空间、空间在哪。三个待验证假设：

1. **骨架掩码**：JSON 的键名、引号、括号等固定字面量不含判别信息，把它们的 loss 权重置 0，
   省下的梯度预算是否会让给语义字段（假设：隐式推理与修辞类受益）。
2. **字段加权**：对难例字段（hard_case 4.0×）加权、对长文本字段（evidence 0.4×）降权，
   能否进一步拉升 hard_case F1（假设：难例类受益，风险在 evidence 与基本盘）。
3. 加权若失败，失败发生在哪一层（容量挤压 / 证据链路 / 输出稳定性）。

---

## 2. 方案设计

三组配置只差 loss 权重矩阵，其余全部锁死。

| 组 | 阶段 | loss 权重设计 | 验证假设 |
|---|---|---|---|
| **R1** | POC1 | prompt 段掩码，output 全 token 权重 1.0 | 基准 |
| **R2** | POC2 | + 骨架掩码：JSON 静态模板 token 权重 0.0 | 死语法不学，容量让给判别 |
| **R3** | POC3 | + 字段加权：hard_case 4.0× / sentiment·relevance 3.0× / risk 2.0× / evidence 0.4× | 难例加权拉升 F1 |

旁证组 **R1_Anchor**（POC1 + 10% 通用锚点数据，不在本报告主对比内，用于交叉验证 R2 增益的量级）。

## 4. 发现与结论

### 4.1 骨架掩码（POC2）是同步改善：全部指标不动或变好

POC2 只做了一件事：JSON 固定字面量（键名、引号、括号）的权重置 0。效果集中在需要语义推理的类别：

- `metaphor` 34.4 → 44.8（**+10.4pp**）、`fact_implicit` 58.7 → 65.0（+6.3）、`multi_subject` 42.9 → 48.2（+5.3）
- hard_case Macro-F1 净涨 +3.14pp；think 闭合 100%；evidence 99.6%；其余副指标无一回落

解释：LoRA 可训容量有限，POC1 下死模板 token 也参与梯度竞争；屏蔽后容量全部流向判别字段。
受益的恰好是隐式推理与修辞类，与「容量重新分配」的机制预测一致。

### 4.2 字段加权（POC3）未胜出：三重代价超过难例收益

实验前预期「难例给 4 倍权重，指标应更高」，实测 hard_case F1 反而降 0.46pp。三个原因：

1. **容量挤压**。4.0× 权重确实拉升了 counterfactual（+4.2）与 comparative（+3.6），
   但把 explicit（−5.7）、fact_implicit（−3.2）、multi_subject（−1.6）拉下来，
   基本盘（support 占约 70%）的损失抵消了难例收益。LoRA r=16 的容量是零和的。
2. **evidence 降权破坏证据链**。evidence 是判别结论的依据字段，0.4× 后子串率 99.6% → 98.8%
   （失败 2 条 → 6 条），依赖证据定位的 governance 风险类 F1 从 30.8 腰斩至 15.4。
3. **JSON 100% 不是真实增益**。gate4 转绿来自闭集字段高权重使 logits 尖锐化，
   靠牺牲 evidence 精度换来。

### 4.2b R3 的 gate4 PASS 从哪来：样本级定位

R2 与 R3 的 gate4 差异只在 JSON 一项（99.6% vs 100%，门限 ≥99.8%），think 闭合两组同为 100%。
R2 的 2 条失败样本逐条定位如下：

| 行号 | 失败形态 | 具体内容 | R3 同行 |
|---|---|---|---|
| #245 | **输出截断** | CoT 写到 `"multi_subject` 处被 1024 生成预算掐断，JSON 未吐出 | 正常输出 |
| #400 | **引号未转义** | evidence 含原文内嵌引号 `被归进"压舱石"一档`，`json.loads` 报 `Expecting ',' delimiter` | 正常输出 |

R3 治好了这两条（高权重使模型在这两条上输出更完整、引号处理正确），但同时在 **6 条**上产生
evidence 非子串（改写原文的幻觉句），例如：

- #350：`Redmi K70这次真的坑，后悔死了，避雷`（金标原文无此句）
- #365：`碧桂园天玺这回可真'过分'，报修当天就有人对接…`（拼接改写）
- #396：`真正厉害的是中国平安…这份'稳'`（改写）

**交换结构：2 条随机格式失误（截断 + 转义）↔ 4 条新增内容幻觉。** 格式失误是随机性的、
可通过推理预算与数据转义规范消除（后续 R6 已用 MAX_NEW_TOKENS=1024 消灭截断类）；
幻觉是内容性错误，只能靠证据链训练强度保证。这也是判定 R2 胜出的核心依据：
不为 2 条可修复的格式毛刺，接受 4 条内容幻觉 + 基本盘受损。

### 4.3 判定

**POC2 胜出，作为 SFT 阶段固定配置。** 依据：主指标最高、格式副指标不降、无证据代价。
R3 的 gate4 PASS（JSON 100%）与 R2 的 99.6% 只差 2 条样本，不值得为此引入 evidence 损耗。

### 4.3b ROI 口径：本组实验的业务读法

负向识别的复核成本由 FAR 决定。三组 FAR 11.2~12.9%（每报 10 条负面约 1 条误报），
组间差异在噪声内——Loss 结构的选择不改变业务成本。ROI 的收益来自「SFT 对比裸基座」
这一步（FAR 34.3% → 12.9%，误报工单约降六成），以及后续的数据规模轴（R7 进一步降至 9.4%）。
对业务侧的表述：选 POC2 的依据是判别力与格式稳定（hard_case +3.1pp、evidence 无损、
think 闭合 100%），而非 ROI；三组业务成本同价位，选了质量最好的一个。完整的 ROI 演进表
（E3 → R2 → R7）见总表报告。

### 4.4 难例攻坚的归属

本组实验同时给出了负结论：**静态 loss 加权攻不动 irony / metaphor**。R3 的 irony recall（60.0）
三组最低。难例判别需要的是「对同一输入采样多个候选、按结果好坏调整」的机制，这是 GRPO 的形态；
SFT 的加权是施加在梯度上的静态先验，只会在容量内重新分配损失，不产生新的判别能力。

### 4.5 旁证：R1_Anchor 的增益量级交叉验证

POC1 + 10% 通用锚点数据（不在本对比主轴上）取得 hc 60.16，高于 POC2 的 59.09。
两个独立干预（数据组成 / loss 结构）在 POC1 基础上各带来 +4.2 / +3.1pp，
量级相当、机制不同（前者补语言多样性，后者重新分配梯度），互不排斥——
后续实验将两者叠加（见数据组成与规模报告）。
