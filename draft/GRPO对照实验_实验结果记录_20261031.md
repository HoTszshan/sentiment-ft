```bash
python3 - <<'EOF'
import json
from collections import Counter
def norm(s): return ''.join((s or '').split())
rows0=[json.loads(l) for l in open('/root/autodl-tmp/models/grpo_senti/run_20261102_111727_g0_v2_part0/grpo_probe_kstats.rows.jsonl')]
rows1=[json.loads(l) for l in open('/root/autodl-tmp/models/grpo_senti/run_20261102_111821_g0_v2_part1/grpo_probe_kstats.rows.jsonl')]
recs0=[json.loads(l) for l in open('/root/autodl-tmp/datasets/rl_round2/train_part0.jsonl')]
recs1=[json.loads(l) for l in open('/root/autodl-tmp/datasets/rl_round2/train_part1.jsonl')]
pool433=[json.loads(l) for l in open('/root/autodl-tmp/datasets/rl_round1/grpo_pool_g1p.jsonl')]
evals={norm(x.get('input_text') or '') for x in (json.loads(l) for l in open('/root/autodl-tmp/datasets/rl_round2/grpo_eval_prompts.jsonl'))}
def is_blind(m):
    return (m['hard_case_type']=='multi_subject' and m['sentiment']=='negative' and m['relevance']=='passing') \
        or (m['hard_case_type']=='counterfactual' and m['sentiment']=='negative')
seen={norm(x.get('input_text') or '') for x in pool433}
merged=[]
def tag(x, why):
    x=dict(x); m=dict(x['meta']); m['rescue']=why; x['meta']=m; return x
for rows,recs in [(rows0,recs0),(rows1,recs1)]:
    for r in rows:
        x=recs[r['idx']]
        h=norm(x.get('input_text') or '')
        if h in seen or h in evals: continue
        m=x['meta']
        if 1<=r['k']<=3: seen.add(h); merged.append(tag(x, f'keep_k{r["k"]}'))
        elif r['k']==4 and is_blind(m): seen.add(h); merged.append(tag(x, 'whitelist_k4'))
        elif r['k']==0 and is_blind(m): seen.add(h); merged.append(tag(x, 'rescue_k0'))
full=pool433+merged
out='/root/autodl-tmp/datasets/rl_round2/grpo_train_prompts_final.jsonl'
with open(out,'w') as f:
    for x in full: f.write(json.dumps(x,ensure_ascii=False)+'\n')
cs=Counter(x['meta']['sentiment'] for x in full)
pn=sum(1 for x in full if x['meta']['hard_case_type']=='multi_subject' and x['meta']['sentiment']=='negative' and x['meta']['relevance']=='passing')
cf=sum(1 for x in full if x['meta']['hard_case_type']=='counterfactual' and x['meta']['sentiment']=='negative')
rc=Counter(x['meta'].get('rescue') for x in merged)
print('冻结池:', len(full), '(433 +', len(merged), ')')
print('sentiment:', dict(cs), 'neg%:', round(cs['negative']/len(full)*100,1))
print('盲区: pn', pn, '/ cf', cf)
print('v2来源:', dict(rc))
EOF
```

- → 冻结池 1877 条 (433 + 1444)；negative 754 = 40.2%；盲区 pn 46 / cf 163
- → v2来源: keep_k1/k2/k3 = 224/305/777 + whitelist_k4 115 + rescue_k0 23

**为什么补捞 k=0 盲区 23 条**——标准 k 筛按「k=0 全错 → RL 无梯度」整组丢弃，但对本 round 的两个盲区桶，
k=0 恰恰是最珍贵的样本：它们是 **G1' 终评实证漏报题型**（gold500 漏报 4 条全部是
relevance=passing 的顺带提及型负向 + counterfactual 反事实负向），如果训练池继续没有这类题，
「训练分布 ≠ 考卷分布」的病根就不会被修复。捞出它们不是指望出梯度（8 采全错的题组内优势全零，
大概率到训练结束仍是能力边界——G0b 的 15 条 k=0 残留已验证），而是
**让池分布对齐考卷分布 + 给这类题一次在 RL 中被「顺带推」的机会**
（同批数据里白名单 k=4 同类题有组内方差，共享梯度方向）。

**之前实验差哪些数据**（扩池前后盲区账）：

| 盲区题型 | 433 池（G1'） | 本轮最终池 | 考卷占比（gold500 neg=166） |
|---|---|---|---|
| passing×negative（顺带提及型负向） | **5**（1.2%） | **46** | 23 条（13.9%） |
| counterfactual×negative（「幸亏没X」） | 39 | **163** | — |

**为何只捞盲区 23 条、不捞全部 k=0（293 条）**：v2 全量 k=0 共 293 条（negative 仅 74），
捞全部会让 ~270 条大概率整训期零梯度的题摊薄采样预算；盲区 23 条（passing×neg 12 + cf×neg 11）
是定向补课，且失效性质为「真判错」而非协议崩场（k=0 组内 reward 均值 −1.32，均值 < −2.0 仅 16/293）
——题是好的，模型是真不会。逐条 meta 加 `rescue=rescue_k0` 留审计标记（白名单 k=4 同理 `whitelist_k4`）。

**结论：「池内难题 ≠ 考卷漏报题」假设成立，且比预想更具体**——
4 条漏报**全部是 relevance=passing**（目标主体仅顺带提及的负向场），而 433 训练池里
passing×negative 只有 **5 条**（占池 1.2%）。gold500 的 negative 共 166 条中 passing 占 23 条（13.9%），
漏报集中在它身上不是巧合：**训练分布里「主角不是我、负向是别人的、我只被捎带」这类题几乎缺训**。
且 G1' 比 SFT 多丢 2 条（277/423 从 negative 滑到 neutral），补捞难题池放大了「宁判 neutral 不判负」的保守漂移——
与 negP +2.43→−0.12 的回吐同源。

**对 P0-2 扩池的定向指令**：negative 难例生成配额从「irony/弱负向」转向
**passing×negative（顺带提及型负向）+ counterfactual×negative（「幸亏没 X」反事实负向）**；
这两类正是 k 筛 + 补捞都没覆盖的盲区（k 筛按整体 reward 筛题，看不见「提及位置」这个维度）。

## CoT 压短安全性核查（2026-11-03，G1'' 11-03 版 pred 实测）

> 背景：11-03 重跑后 CoT p50 实测降至 186（`<think>` 内层口径）/ 230（`count_cot_tokens` 口径），
> 引发「压穿 120 地板 → 推理空壳化」担忧。核查方式：对 500 条终评输出按
> `lib/reward_fns.py` R_length 同源三档分桶 + 短例逐条抽查。

### 1) 500 条 CoT 档位分布（count_cot_tokens 口径，p50=230 / p95=329 / p99=367）

| 档位 | 条数 | 占比 |
|---|---|---|
| 过短 <120（R_length 罚分区） | **1** | **0.2%** |
| 理想 120~200（满分带） | 159 | 31.8% |
| 衰减 200~320 | 310 | 62.0% |
| 归零 ≥320 | 30 | 6.0% |

**分布主体停在 200~320 衰减带，无向 120 以下坍缩迹象。**

### 2) 为什么不会越压越短（机制层）

1. R_length 硬地板 `<120 → n/120−1` 是**线性罚分**（115 tok 拿 −0.04，60 tok 拿 −0.5），
   压短梯度只到 120~200 满分带为止，过线反向；
2. R_length 仅在「判对 + 溯源过门」时激活——压缩不能拿 accuracy 换长度分；
3. 唯一短例（115 tok）抽查：三跳结构完整（相关性 → 难型 → 风险+情感），判对——
   是「表达紧凑」不是「推理空壳」。

### 3) 判别力同步无回退

negP 92.05（四轮最高级）、hard_case F1 **78.11（四轮历史最高）**、irony F1 86.75——
压短最凶的一轮恰是判别最强的一轮，R_length 是塑形不是截断的直接证据。

### 4) 监控口径（触发才动手，平时不动）

- **short<120 占比 >5%** → 压穿地板，`COT_SHORT` 120 上调至 140~160（一行常量）；
- **irony / counterfactual recall 先升后跌** → 三跳被压瘪前兆，`COT_DEAD` 320 放宽至 360；
- 当前两条均未触发。

### 5) 架构稿口径修正（防串号）

设计稿「单次解码 ~180 → 65~105 tokens」：起点 ~180 已实测兑现（186 ≈ 180），
**65~105 未达成且不应硬凑——按纪律改稿不改数**。对外口径统一为：
**CoT p50 273 → 186/230 token（−19% ~ −32%，两把口径），分布主体留在 200~320，
无空壳化。**

> 口径备注：186 = `<think>` 内层正则提取 + Qwen tokenizer；230 = `count_cot_tokens`
